# 静态交互原型开发

交付可运行、可演示、便于迭代的静态前端原型。默认沿用分层结构，产品内容与视觉随需求调整。

## 工作模式

| 模式 | 开始前查看 | 工作重点 |
|---|---|---|
| 新建 | 需求、参考材料、目标目录及已有文件 | 明确角色、页面与核心流程，建立最小可用结构 |
| 迭代 | 项目规范、相关代码、依赖与当前改动 | 沿用现有结构与视觉，完成受影响的流程 |
| 协作共建 | 分工、共享接口与仓库约定 | 明确模块边界，减少共享文件冲突，验证集成 |

- 优先遵守用户选择与项目规范；不因使用本技能迁移框架或全面重构。
- 信息足够时直接实现；缺少关键角色、流程或验收目标时简短询问，并继续不依赖答案的工作。

## 默认结构

```text
项目/
├── pages/
│   ├── role-a/              # 角色 A 的 HTML 页面
│   └── role-b/              # 角色 B 的 HTML 页面
├── assets/
│   ├── css/                 # 公共与业务样式
│   ├── images/              # 图片资源
│   └── js/
│       ├── core.js          # 命名空间与基础能力
│       ├── nav.js           # 公共导航
│       ├── feature.js       # 业务模块
│       ├── feature-store.js # 跨页数据与浏览器存储
│       └── pages/
│           ├── role-a/      # 页面专属脚本
│           └── role-b/
├── data/                    # 模拟数据与页面配置
├── docs/                    # 必要的架构与协作约定
└── README.md                # 说明、入口、预览方法
```

- 用实际角色与业务名替换示例；按需建目录，简单页面无需强行增加模块或存储层。
- 新项目默认 HTML、原生 JavaScript、CSS，无构建步骤。使用普通 `<script src>` 与相对路径，保持直接打开 HTML 的能力。
- Tailwind CDN、图表库等按需使用；说明联网依赖，离线需求使用本地资源。

## 分层与接口

| 层 | 职责 | 边界 |
|---|---|---|
| HTML | 布局、容器、资源加载、静态文案 | 复杂逻辑放入脚本 |
| 页面脚本 | 初始化、页面配置、本页交互 | 位于 `assets/js/pages/<角色>/` |
| 业务模块 | 渲染、事件与业务操作 | 按业务职责拆分，供页面复用 |
| Store | 跨页读写与状态恢复 | 不操作 DOM |
| Data | 初始样例、数据工厂、演示配置 | 不操作 DOM 或存储 |
| 公共界面 | 导航、通知、弹窗、主题 | 修改后检查使用方 |

- **接口**：新项目以 `window.Prototype` 暴露必要 API，如 `Prototype.courseStore.*`；内部函数留在闭包中。迭代保留已有命名空间。
- **加载**：按依赖安排 `core → data → store/依赖模块 → 业务模块 → 页面脚本`；操作 DOM 前确保容器已加载。
- **跳转**：同角色用 `./xxx.html`，跨角色用 `../role-b/xxx.html`；统一 URL 参数并按需编码。
- **数据**：数据工厂返回独立对象；跨页共享稳定业务 ID，需要闭环的列表、详情与编辑通过同一 Store 读写。
- **存储**：按需持久化，明确保存范围；迭代保留存储键与用户记录，结构变化提供兼容读取或迁移。
- **预览**：直接打开文件时不依赖 `fetch` 本地 JSON 或 ES 模块；确需静态服务时说明启动方式，以同源服务验证跨页存储。

## 开发流程

| 步骤 | 新建 | 迭代 |
|---|---|---|
| 确认范围 | 角色、页面、核心操作与验收结果 | 修改入口、依赖与受影响页面 |
| 组织代码 | 建必要目录、主题、导航与数据 | 沿用现有分层，按需局部拆分 |
| 实现流程 | 先打通一条核心流程，再补相关页面 | 同步修改页面、逻辑与数据 |
| 完善状态 | 补空态、校验、操作反馈与结果 | 补新增状态与跨页读写 |
| 验证交付 | 检查入口、流程与运行方式 | 回归变更流程及共享模块使用方 |

- 核心按钮完成操作、导航或明确反馈；未实现入口标明状态。
- 演示数据覆盖核心流程，列表、详情、编辑与结果保持一致；独立统计快照注明演示性质。
- AI、上传、发布等可模拟实现，但操作反馈应明确实际效果，避免暗示已连接真实服务。
- 复用主题与公共界面，统一表单、弹窗和反馈，适配目标演示设备。

## 协作共建

- 有共建需求时，在 `docs/` 简要记录分工、共享 API、业务 ID、存储键、脚本依赖与合并约定。
- 优先按业务模块或角色页面分工；修改核心、导航、主题、公共样式或 Store 时查清使用方，同步接口与调用方。
- 按仓库约定使用功能分支；保留他人未提交改动，冲突结合双方意图解决并重新验证。
- 模块协作先明确输入、输出与数据所有权，避免重复实现同一存储或公共组件。
- 多人共建不自动启动子代理；仅在用户或项目规范要求委派时按文件边界分配并统一集成。
- 提交、推送、PR 与部署遵循用户授权及仓库规则；技能本身不授予这些权限。

## 验证与交付

| 检查 | 内容 |
|---|---|
| 静态检查 | JS 语法、资源路径、加载顺序、接口调用与页面链接 |
| 流程检查 | 浏览器中的核心点击路径、表单反馈、跨页数据；有存储时检查跳转与刷新恢复 |
| 共享回归 | 公共模块涉及的角色与页面、目标尺寸下的关键布局 |
| 运行说明 | README 中的入口、预览方法、依赖与模拟功能；必要时同步架构文档 |

- 按影响范围验证；小型文案或样式修改不建立重型测试体系。
- 无法执行的检查说明具体限制与未验证项，不把未运行的检查写成已通过。
- **输出风格**：结构化、简洁，优先短表格、目录树和平级清单；避免长篇过程复述。
- **完成报告**：实现内容、入口/文件、验证结果；仅有实际影响时补充限制或待办。
